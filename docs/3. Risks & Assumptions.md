# Assumptions

## Product Assumptions

- The MVP targets exactly one authenticated browser workflow on one website.
- The recorded workflow is deterministic and repeatable.
- The user records a valid, successful browser session.
- The target workflow requires only browser interactions supported by Playwright.

## Technical Assumptions

- The Ollama service runs successfully on the developer's local machine with the chosen model pulled (confirmed per the hardware tier table in `4. Tech-Stack.md`).
- The local model (e.g., `qwen2.5-coder:7b`, `llama3.1:8b`) produces reliable structured JSON output for the narrowly constrained Pattern Extractor and Code Generator tasks within an acceptable retry budget.
- If the local model proves insufficient for a specific step, the Groq free API tier is available as a zero-cost fallback with no credit card required.
- Claude Desktop continues supporting MCP-based integrations. Claude Desktop is used only as the runtime MCP host (a chat client), not as an API backend.
- Playwright maintains compatibility with the supported Chromium version.
- Python and project dependencies remain available in supported versions.
- Internet connectivity is required only when the optional Groq fallback is active. The default Ollama path runs fully offline.

## Security & Privacy Assumptions

- Sensitive credentials can be identified and redacted during recording.
- Local execution satisfies the project's privacy requirements.
- No browser data leaves the machine except intentional LLM API requests.

## Project Assumptions

- The execution plan will be followed sequentially without skipping phases.
- Generalization to multiple websites is deferred until Phase 8.
- Security, validation, and testing phases will not be skipped even if earlier milestones are completed ahead of schedule.
- The project will remain focused on producing a robust, interview-ready MVP rather than a production-scale automation platform.
