# Technology Stack

## Core Technologies

| Layer | Technology | Version Policy | Rationale |
|-------|------------|----------------|-----------|
| Language | Python | **3.13 (Minimum: 3.11+)** | Modern async ecosystem, excellent Playwright support, strong typing, and broad library compatibility. |
| Browser Automation | Playwright (Python) | Latest stable (pinned) | Reliable, cross-browser automation with built-in code generation, tracing, and robust locator APIs. |
| Browser | Chromium | Latest Playwright-managed version | Single-browser support minimizes variability and simplifies debugging during MVP development. |

Pattern Extractor: `llama3.1:8b` (general reasoning). Code Generator: `qwen2.5-coder:7b` or `qwen2.5-coder:14b` (code-tuned). Confirm current tags at `ollama.com/library`. |
| LLM Backend (Fallback) | Groq free API tier | OpenAI-compatible endpoint; no credit card required | Genuinely free (no billing), suitable when local model is too slow or unreliable for a specific step. Rate-limited (~30 req/min, ~14,400 req/day — verify at `console.groq.com/docs/rate-limits`). |

| Validation | Python `ast` + `jsonschema` | Python stdlib + latest stable (pinned) | AST validation prevents unsafe generated code, while JSON Schema enforces structured LLM outputs. |
| Serialization | JSON | — | Standard data exchange format between all pipeline stages. Answers the common interview question: "what format do your pipeline stages use?" |
| Storage | JSON + SQLite | SQLite latest stable | JSON stores workflow artifacts, SQLite manages lightweight metadata while keeping execution local-first. |
| Testing | pytest | Latest stable (pinned) | Standard Python testing framework supporting unit, integration, and end-to-end tests. |
| Logging | Python `logging` (structured JSON output) | Python stdlib | Every component emits structured JSON logs for tracing, retries, and diagnostics. Defined at the stack level to prevent ad-hoc logging patterns. |
| Dependency Management | uv + pyproject.toml | Latest stable | Fast dependency resolution, reproducible virtual environments, and modern Python project management. |

| Version Control | Git + GitHub | Current | Source control, collaboration, reproducibility, and portfolio visibility. |

# Dependency Management

- Use **uv** for virtual environment creation and dependency installation.
- Define all project dependencies in `pyproject.toml`.
- Commit the generated lock file (`uv.lock`) to ensure reproducible environments.
- Separate dependencies into:
  - Runtime
  - Development
  - Testing

---

# Version Pinning Policy

- Pin all direct dependencies to exact versions in the lock file.
- Avoid floating major versions.
- Update dependencies only after compatibility testing.
- Record significant upgrades in the project changelog.

---

# Upgrade Policy

- Review dependency updates before each development milestone.
- Apply security patches promptly.
- Upgrade one dependency group at a time.
- Run the complete validation and regression suite after every upgrade.
- Do not upgrade packages immediately before demonstrations or interviews.

# Development Principles

- Local-first architecture.
- Deterministic template-based code generation.
- Strict JSON contracts between pipeline stages.
- Schema validation for all LLM outputs.
- AST validation before executing generated code.
- Security and validation take precedence over feature expansion.
- Reproducible builds and deterministic environments are mandatory.

---

---

# Concurrency Model

- Async-first using Python `asyncio`.
- Playwright async API throughout the pipeline.
- Single event loop per pipeline run.
- No multithreading in MVP.

# Technology Selection Rationale

The chosen stack aligns with BrowserBot's architectural goals:

- **Python** provides the strongest ecosystem for Playwright, async workflows, and AI tooling.
- **Playwright** eliminates the need to build a custom browser recorder.
- **Ollama** provides a $0-marginal-cost, fully-offline LLM backend for both the Pattern Extractor and Code Generator agents. Using a local model makes the "local-first, zero-cloud-account" privacy claim literally true rather than carving out an exception for LLM calls.
- **LiteLLM abstraction** decouples agent code from the underlying LLM provider. Switching from Ollama to Groq (or any future provider) is a one-line config change.
- **Groq free tier** provides a genuine $0 fallback for developers whose hardware cannot run a capable local model at a usable speed, without requiring a credit card.
- **Claude Desktop** remains the runtime MCP host — a chat client, not a billed API, unaffected by the zero-budget constraint.
- **FastMCP** simplifies exposing generated browser automations as installable MCP tools.
- **Jinja2** guarantees deterministic server scaffolding while limiting LLM-generated code to business logic.
- **AST validation** and **JSON Schema** enforce security and correctness before execution.
- **uv** and **pyproject.toml** provide fast, reproducible dependency management suitable for an interview-ready engineering project.
